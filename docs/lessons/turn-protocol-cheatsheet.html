A术语

四个不要混用的词

Thread

跨多轮的对话容器。官方语义包含可恢复的历史；本项目 Runtime MVP 目前主要用它分组事件。

Turn

一次用户请求及其后续 Agent 工作，直到 completed、failed 或 interrupted 等终态。

Item

Turn 内单个可观察输入/输出：消息、命令、文件变更、工具调用等。当前项目 Runtime API 尚未建模。

LLM call

一次模型请求。ReAct Turn 里可能发生多次；它是实现步骤，不是用户层事务边界。

Thread 1 ─┬─ Turn A ─┬─ user input
          │          ├─ LLM call
          │          ├─ tool call
          │          └─ final answer
          └─ Turn B ─┬─ user input
                     └─ ...
B本地调用链

两条 Turn 路径

交互式执行与快照

Main / TuiSessionController
  → SnapshotService.runTurn(mode, input, work)
    → preTurnSnapshot
    → Agent.run | PlanExecuteAgent.run | AgentOrchestrator.run
    → finally: postTurnSnapshotAsync

Runtime HTTP 协议

POST /v1/threads
  → RuntimeThreadStore.createThread

POST /v1/threads/{id}/turns
  → turn.started
  → executor.submit(runTurn)
  → fresh headless Agent
  → message.delta + turn.completed | turn.failed

GET /v1/threads/{id}/events?after=N
  → ordered persisted events as one SSE-formatted response
C判断题

读代码时快速校准

一次工具调用就是 Turn？否。它只是 Turn 内的一个动作或 Item。
Plan 的每个 DAG 节点是 Turn？否。整个用户 Plan 任务才是快照 Turn。
Runtime Thread 会保留聊天上下文？当前不会。它持久化 thread 标识与事件，每轮新建 Agent。
message.delta 真正逐 token？当前不会。runner 完成后一次写入完整 result。
Runtime Turn 自动建立 side-git 快照？当前不会。该 runner 未经过 SnapshotService.runTurn()。
