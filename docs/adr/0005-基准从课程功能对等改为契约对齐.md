# ADR-0005：功能基准从课程功能对等改为 Claude Code 契约对齐

本项目的功能基准不再是课程 `sNN_topic/code.py` 的逐项功能对等，改为 **Claude Code 的公开契约**：
`@anthropic-ai/claude-agent-sdk` 的 `.d.ts` 与官方文档定「接口和行为必须长什么样」，冲突时以契约为准；`code.py` 降为
「同一契约的一种简化解法」。项目目标是理解 Claude Code 的构造，而 `code.py` 是第三方对同一套契约的简化解读 ——
把它当唯一基准，学到的是课程作者的抽象，不是 Claude Code 的抽象。

## 为什么是契约，不是实现

「对齐真实实现」这条路查证后走不通。`@anthropic-ai/claude-agent-sdk@0.3.233` 拆包后，`sdk.mjs` 是 1.3 MB 的 minified
产物，文件头明确写着 `Want to see the unminified source? We're hiring!`，真正的 harness 打进了 Bun 二进制
（`extractFromBunfs.js` + `manifest.zst.json`）。但同一个包里 `sdk.d.ts` 8043 行加 `sdk-tools.d.ts` 3896 行**完全可读**：
permission 模式、hook 事件、每个工具的 input/output schema、消息类型全在其中。

即**实现细节拿不到，接口契约完整可得**。这决定了基准只能定在契约层：契约约束接口和行为，内部怎么实现是自由度。

## 来源分三层

契约层（`.d.ts`、官方文档、可观测的运行时行为）定「必须长什么样」；课程 `code.py` 回答「别人怎么解」；
<https://github.com/liuup/claude-code-analysis> 的 `analysis/` 18 章回答「他们为什么这么做」，其 `src/` 的 51 万行不读。

第三层的位置是刻意压低的，有三个理由。它是 2026-03-31 的快照，而 Claude Code 按周演进，当**契约**基准打不过当前的
`.d.ts`；51 万行读不完，读了也是噪音，而 `analysis/` 是已经做完的提炼；该仓库自述权利属 Anthropic 并提供下架通道，
`sdk.mjs` 头部也指向 legal agreements，条款风险由使用者自负。

## 课程为什么仍然留着

课程 17 课的清单与 Claude Code 的真实工具表近乎 1:1 —— Skill、Agent（subagent）、SendMessage/ListAgents（agent teams）、
Monitor（background tasks）、Cron、Workflow、memory、hooks 一一对应。它显然是照着真实能力面逆向排的，所以**路线图可靠**，
17 课全做。变的只是它的角色：从「必须对等的基准」变成「同一契约的另一种解法」，而这个角色恰恰有独立价值 ——
对照两种解法能看到「为什么他这么裁、我那么裁」，这是单看契约得不到的。

## 代价

`code.py` 对等虽然绑得死，但它给了一个**机械可核对**的完成判据：逐字比对函数体即可。换成契约对齐后，
「hook 管线算实现完了吗」没有现成答案，每个能力的验收线要自己定。这是这个决定唯一实质的损失，不是白赚。

两条机制用来兜住它。**名全录、行为按需**：契约里的枚举值和事件名全部录进类型（成本只是一个 enum），行为实现按端到端
场景裁剪，未实现的显式标记 —— 于是「没实现」是显式待办而不是遗漏，这一点 `code.py` 对等做不到，漏了不会有人告诉你。
**验收三分工**：契约核对定「做什么」，端到端场景定「做完了」，单元测试只保护真会写错的边界逻辑。

## 什么会推翻这个决定

`.d.ts` 若大幅收窄（官方把 hook、permission 这些用户可配置的契约移出公开类型），契约层就不再够用，届时需要重新评估
是否退回 `code.py` 对等，或把第三层提为主要来源。
