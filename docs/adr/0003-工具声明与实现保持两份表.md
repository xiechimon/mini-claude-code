# ADR-0003：工具声明与实现保持两份表，不聚合成单一 Tool 对象

s02 起工具由 1 个增至 5 个，Tool Definition 与 Tool Handler 保持为两份互不校验的独立数据：`ToolRegistry` 持有 `List<Tool>`
声明表和 `Map<String, ToolHandler>` 实现表，`AgentLoop` 只按 Tool Call 的工具名查实现表，查不到时把 `Unknown: {name}` 当作 Tool
Result 回填并继续循环。不采用「每个工具一个自带 schema 与执行的对象」的聚合形态。

聚合形态在 Java 里更省事，也是官网所称生产 Claude Code 用 `buildTool()` 采取的形态，但那样会消灭本课唯一的教学点——「加一个工具 =
声明表加一条 + 实现表加一行，循环代码不动」，并让「声明了却没有实现」这条运行时路径在类型层面不可达。两份表的代价是工具名在声明、映射键和实现类三处重复，且没有编译期检查保证两份表键集合一致；这个代价被接受，因为它正是课程要展示的性质。

后续课次增加权限判定（s03）与钩子（s04）时会重新形成聚合压力：那些能力天然按工具挂载，聚合对象是自然归宿。届时若决定聚合，应作为一次显式的结构演进另立
ADR 取代本篇，而不是在某个工具上悄悄开始携带自己的声明。
