# ADR-0006：模型调用接缝从同步消息改为事件流

`ModelClient` 的接口从 `Message create(MessageCreateParams)` 改为 `Stream<ModelEvent> events(MessageCreateParams)`，
事件流只暴露两个时机：文本增量 `TextDelta` 与消息完整 `MessageComplete`。Agent Loop 从「同步拿整条消息」改成
「消费事件流」，流式与非流式只是接缝两侧的两个实现。本决定取代 ADR-0002 中「`Message create` 为精确接口」的表述。

## 为什么是事件流，不是旁路 sink

要支持流式输出，非流式接口 `Message create` 拿不到增量文本，必须换 API。换法有两条：一条是保留同步返回、加一个
旁路回调专门收增量（改动小），一条是把接缝整体改成事件流（改动大）。选后者，因为旁路 sink 只有「文本增量」一个
扩展点，而后续课次需要的是「响应生命周期」上的多个时机——s08 compaction 要在消息到达过程中、内容超预算时截断，
s15 的权限要在 tool_use 完整时触发。这些都必须落在事件流上才挂得上，旁路 sink 承载不了。

代价是 Agent Loop 的核心循环从同步读改造成事件消费，非流式实现也必须重写以产出同一种事件。这个代价换取的是接缝
的长期复用：后续每课不再改接缝形状，只在事件流上新增时机。

## 为什么只有两个事件

最初设计是三个事件：`TextDelta` / `ToolUseComplete` / `MessageComplete`。实现前查证 SDK 后发现 `ToolUseComplete`
两头落空，于是砍掉：

- **生产端产不出**：SDK 的 `MessageAccumulator` 只暴露 `accumulate(event)` 与 `message()`，不暴露中间的 tool_use
  block。tool_use 的 input 是 `input_json_delta` 逐段拼起来的，实时产出完整 tool_use 需要自己拼 partial JSON，
  而拼接正是 accumulator 存在的意义——重复造轮子。
- **消费端不想要**：工具执行时机定为「消息完整后统一执行」（见下文），tool_use 只是被收集，收集可以直接从完整
  `Message.content()` 里拆，不需要独立事件。

两事件恰好落在「SDK 真实暴露、且不重复造轮子」的边界上：文本增量来自原始 `contentBlockDelta`，完整消息来自
accumulator。未来若要做「逐个 tool_use 实时批准」，那是新需求驱动的新时机，届时再自己拼 input_json 并引入第三
事件，而不是现在预支一个用不上的时机。

## 工具执行时机不变

流式唯一带来的行为差异是「文本逐字显示」。工具执行仍发生在 `MessageComplete` 之后、`stopReason == TOOL_USE` 时，
一轮内多个 tool_use 仍汇总成一条 user 消息。这样换实现只改显示时机、不改循环语义——可插拔的最小差异。

## 一个顺带的行为修正

非流式路径下，`stopReason == TOOL_USE` 的响应里夹带的文本此前被丢弃（循环只遍历 tool_use 块）。改成事件流后，
所有文本块都会作为 `TextDelta` 打印，包括工具调用之前的文本。这与真实 Claude Code 一致——模型先说一句再调用
工具，那句该显示。这是一次向真实行为对齐的修正，不只是重构。

## 什么会推翻这个决定

若 SDK 后续在 `MessageAccumulator` 之外提供「按 content block 粒度取中间结果」的高层 API，`ToolUseComplete`
时机的生产成本会降到可忽略，届时可重新评估是否恢复三事件。若 Agent Loop 未来需要在消息完整之前就干预内容
（例如边收边 compaction），两事件的粒度不够，也需要引入更细的事件。

## 本 ADR 的修订（2026-08-17）

SDK 2.53.0 已直接暴露 content block 粒度的中间结果：`RawContentBlockStartEvent` 的 `contentBlock().toolUse()`
和 `contentBlock().thinking()`，以及 `RawContentBlockDelta` 的 `inputJson()` 和 `thinking()`。生产成本已可忽略。
同时流式 UX 需在事件流上实时显示 tool_use 和 thinking——两事件粒度不够。

因此新增三个事件，总事件从 2 个变为 5 个：

- `ModelEvent.ToolUseStart(int index, String name, String id)` — 来自 `contentBlockStart` 的 tool_use 块
- `ModelEvent.ToolUseDelta(int index, String partialJson)` — 来自 `contentBlockDelta` 的 `input_json_delta`
- `ModelEvent.ThinkingDelta(int index, String thinking)` — 来自 `contentBlockDelta` 的 `thinking_delta`

其中 `index` 是 SDK 分配的 content block 序号，从 `RawContentBlockStartEvent.index()` 和
`RawContentBlockDeltaEvent.index()` 直接映射，不与 `MessageAccumulator` 交互。

本次扩展不推翻 ADR-0006 的任何既有结论，是其「什么会推翻」节预言的两条路径的汇合。
